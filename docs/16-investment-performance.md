# M3.3 第二阶段：历史边界与期间总盈亏

状态：第二阶段已实现，0.10.0 待 PR 合并。

## 范围与口径

沿用投资报表的月／年／自选日期与账户、标的、类型筛选，在同一只读事务内按当前有效事实重建开始日前一天、截止日收盘持仓。不是当时保存的冻结报表；后补和修订会重算，不新建快照表，不变更 schema v7。

期间总盈亏＝期末持仓市值－期初持仓市值＋期间投资现金净变动。包含未卖出持仓的市值变化与现金分红；买卖本金抵消，再投增加份额且仅另付费用流出，分红与费用不再重复加减。现金到账另一账户仍按持仓归属。普通转账、收支、账户现金余额不进入公式。

非零持仓必须有边界当天的有效手动价格，且通过既有分红／折算后的价格门槛。不使用未来价格，不把此前价格当作边界真实净值，不推算周末价格；缺价列出持仓与所需日期，总值和盈亏未知，另保留已知市值小计。空仓市值零。未知成本不阻止市值差法计算。

期间新增期初持仓表示期初范围不完整，即使填写成本也不能代替外部注入市值，本阶段总盈亏未知，提示选择期初记录之后的开始日期。无持仓也无事件时盈亏零。边界持仓展示账户、标的、份额、剩余成本、市值、价格日期和缺价原因。期间报表 CSV 同步附带边界与盈亏字段，可追溯账本版本。

## 验收

1. 独立算例覆盖跨期买卖、买入费用、卖出净到账、现金分红到账其他账户、再投费用、折算、清仓和同日顺序，价格齐全时按市值与现金核对。
2. 缺当日价格、仅有旧价／未来价、作废价格、事件后待确认价格，明确未知而非零；补价后可算，后续事件不得改变较早边界持仓。
3. 期间期初记录提示未知，期间外未知成本但边界价格齐全可算，空期间与空仓零，多账户及筛选独立计算。
4. 历史修改／作废重算，API 与 CSV 金额一致，查询不写账本；前端期间切换与边界提示实际浏览器验证。
5. 运行既有格式、静态、类型、契约、后端和前端测试、构建及 Windows 成品检查。

## 验证与限制

后端完整 157 项测试通过（新增 8 项历史边界与盈亏验收），Ruff、格式与 mypy 通过；OpenAPI 与 TypeScript 契约已同步，前端格式、ESLint、类型检查和构建通过。4 项 Edge 浏览器测试通过，实际核对期初注入的未知提示、股票期间盈亏 388 元、边界份额、筛选与四类下载；合成页面目视检查通过。

当前以个人账本规模为目标，每次读取完整历史并重建两个边界，不承诺大规模性能；估值缺失时只显示已知小计。严格当天估值会要求用户补录两个边界的价格，周末也不自动推算。本阶段无新依赖、无数据库迁移，完整迁移继续使用备份。Windows 成品与 CI 结果以实际验证为准。
