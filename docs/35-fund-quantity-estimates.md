# 基金份额自动预填

## 验收条件

- 定投待核对项净值所属日默认计划日期，可改；实际确认日期仍由用户填写。
- 定投及新建手工基金买入自动按本地该净值日的有效单位净值计算参考份额。精确日期匹配，缺失／作废时提示补价或手填，不取邻近日和最新价格。
- 含费用实际扣款：份额=(扣款-费用)/净值。不含费成交金额：份额=成交金额/净值。用后端 Decimal，默认两位小数 ROUND_HALF_UP，结果小于 0.01 份提示人工核对。
- 份额可手改（最多八位小数），手改值和截图识别份额优先。提供重新按净值计算入口。自动值随日期、标的、金额、费用变化重算，旧响应不得覆盖新输入。
- 计算为认证只读 API，批量最多100项；本地查询，无自动联网和写账。仍经现有预览／保存流程由用户核对后入账。
- 手工计算适用于新建基金买入，股票/ETF、卖出及历史编辑保留原有份额输入。
- QDII 计划日仅作默认值，节假日、15点后和平台暂停以回执为准。净值缺失不推算份额，历史确认记录不改写。
- schema11。合成测试覆盖费用口径、舍入、缺价作废、人工覆盖、字段联动、过期响应与实际保存。

## 实现与验证

0.26.0 已实现。新增认证只读 POST /api/v1/investments/quantity-estimates，精确日期查询有效公募基金净值。314 项后端测试、19 项浏览器测试通过，覆盖独立舍入算例、净额／成交金额、缺失和作废净值、人工覆盖、过期响应、默认计划日期、实际保存内容和原有流程。干净 npm ci、格式、静态、类型、契约、静态构建和本地自检通过。

构建期间发现既有 Next.js 16.4.3 安全提示会中止首次构建，已将 Next.js 及对应 ESLint 配置升级至同系列 16.4.6。升级后重新完成干净安装、静态检查、构建、19 项浏览器测试，生产依赖审计为 0 项漏洞。公告依据 https://github.com/vercel/next.js/security/advisories/GHSA-mfr8-8qww-v76h 。
