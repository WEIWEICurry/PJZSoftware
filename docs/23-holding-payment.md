# 持仓归属与支付账户分离

## 验收

持仓账户代表支付宝／券商的实际持仓归属；买卖的扣款／到账账户独立选择。持仓仍按持仓账户＋标的核算，跨支付银行卡不拆仓；不同持仓平台不自动合并。现有记录默认保持原归属，不自动猜测平台。

历史归并必须先选择标的、来源账户和目标持仓账户并预览。以整段历史为单位转移，保留事件 ID、日期、顺序、份额、费用和原支付账户，修订并审计。提交前验证备份，事务内重放所有成本与现金；冲突整体回滚。预览后账本变化必须重新预览；重复提交不重复迁移。多个期初或事件顺序冲突拒绝，不把期初伪造为买入。相关定投计划同步归属并保留原扣款账户；计划的已确认记录关联保持完整。

schema 10 表示新的支付语义，并为定投增加支付账户；升级前备份，旧版不得打开新账本。本次不提供跨 schema 程序回退。归并前后现金账户余额不变；持仓合并后按合计份额一次估值，分位舍入可能与分行小计相差一分；移动加权成本按合并历史重算，历史卖出成本可能变化，应预览比较。

自动验证：多银行卡买入后同平台仅一仓、卖出超过单卡份额但不超过平台总份额、独立到账、未知成本、负现金回滚、跨平台隔离；归并预览无写入、过期拒绝、保护备份可恢复、定投关联、重试和还原后余额持仓一致。UI 只使用合成数据。

## 本地验证

Ruff 检查与格式、mypy、267 项 pytest、前端格式／ESLint／类型检查／静态构建、5 项 Playwright、契约同步与应用自检均通过。浏览器验证创建平台账户、预览并确认历史归并及既有账务／备份恢复。成品与远端 CI 最终状态见 PR。

归并预览令牌五分钟有效，绑定方案与账本版本；提交成功后失效，原幂等键重试返回原结果。合并多个期初或期初发生在目标既有交易之后会拒绝；请先核对来源，不自动改写期初含义。升级步骤见 README 的 0.18.0 部分。
