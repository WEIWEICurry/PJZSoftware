# 支付宝持仓截图批量对账

## 验收条件

- 投资页独立持仓对账入口。选择持仓账户及截图对应的持仓日期，支持多张资产详情截图（最多 20 张、累计 40 MB，单张 PNG/JPG 5 MB）。
- 沿用按需本地 OCR、内容去重、失败重试和当前原图预览。图片及草稿只留在页面内存。
- 识别基金名、代码、持有份额、持有金额、待确认金额、单位净值和净值日期。字段识别不完整保留未知，允许人工改正。
- 净值只有月日时按持仓日期推定最近的年份并显示提示，人工核对后使用；不从手机时间推定截图日期。
- 每张人工确认后以只读认证 API 批量对账。按所选持仓日期重放账户，屏蔽之后的交易；份额比较与净值日期分离。
- 份额区分精确一致、按截图显示精度一致、存在差异。使用 Decimal，展示本地精确份额和精确差额。
- 同口径参考市值=本地该日期份额×截图单位净值，按分四舍五入。与平台持有金额比较；截图缺净值显示未知。最多一分差额提示舍入差异。待确认金额单列，不加入已确认市值。
- 本地估值和日期另列。日期不同时不直接报告本地估值金额差异；缺本地估值不填零。
- 同批同一基金重复出现时拒绝正式对账，需排除一张。未匹配基金不能完成对账；本地暂无该基金持仓则显示本地零份额。
- 仅覆盖选中截图，账户其他未出现在截图中的标的列为「未提供截图」，不视为零持仓。
- 展示与差异相关的提示，提供跳转原投资记录。修正通过已有投资流程进行。
- 读事务中返回账本版本；对账不保存图片、不新增交易、不改份额成本和净值。schema 11 无迁移。

## 验证要求

合成数据验证双列 OCR 不混金额、带日期净值、跨年推定、字段缺失、截图精度舍入、历史重放、估值日期不同、无持仓、重复基金及只读修订不变。浏览器验证多图识别、重试、逐张修改核对、只读结果和相关记录跳转；完整检查按开发规范执行。

## 实现与验证

0.24.0 已实现。300 项后端测试、16 项浏览器测试通过，覆盖历史重放、精确与显示精度一致、同日及不同日期字段、缺价、未提供截图、重复基金、认证和只读修订不变。双列合成截图经真实本地 OCR 和浏览器对账，验证一致项及份额 -0.03／同口径市值 -4 分的差异项，账本内容和修订号保持原样。干净 npm ci、格式、静态、类型、契约、构建及本地自检通过。

持仓日期需由用户确认。净值仅月日时推定最近年份并提示核对。OCR 字段可修改。结果用于人工定位，修正通过既有投资流程；图片和草稿在清空批次或刷新后清理。
