# 运行与开发指南

## 当前版本：0.7.0 记账与投资便携版

已实现账户与期初、普通收支、退款、转账／借还本金与费用、余额校正、修改／作废、归档、分类和月收支总览。备份包含全部已实现的业务数据、修订和幂等记录。历史汇总可预览导入，预算和收支报表已实现；投资基础使用见文末。

恢复后保留独立副本，不自动切换；用 --data-dir 指向恢复目录可打开该账本。旧版 schema v1～v5 会先备份再升级至 v6；支持 v1～v6 备份恢复，拒绝更高版本。

## 直接运行 Windows 便携目录

双击 dist/PJZSoftware/PJZSoftware.exe，必须保留同目录的 _internal 文件夹。默认浏览器打开界面，启动器提供打开与退出控制；关闭浏览器标签不等于退出服务。

默认数据位置：%LOCALAPPDATA%/PJZSoftware/ledgers/default/。安装资源与账本分离。换电脑时使用备份恢复，不直接复制运行中的数据库。

```powershell
.\dist\PJZSoftware\PJZSoftware.exe --data-dir 'D:\我的账本'
```

不要同时用旧程序操作升级后的账本。回退需使用旧程序与升级前备份，不支持直接降级数据库。尚未提供正式安装／卸载向导及程序签名。

## 开始记账

1. 在“账户”录入账户类型、实际期初日期及余额（负债填欠款）。若要补录历史，期初日期应在这些交易之前。
2. 在“日常账本”选择类型、账户、日期和金额。普通转账选择资金账户两端；借钱／还钱选择“借还款”，再选择具体操作。手续费单独计支出。
3. 退款在原支出行点“退款”发起，允许部分退款且不能累计超过原额；分类沿用原支出。
4. 修改／作废后重新检查完整时间线，余额不足或关联退款失效会拒绝整个操作。期初记录不可直接编辑，差异用“余额校正”并写原因。
5. 归档账户必须零余额；历史记录保留，归档后不接收新流水。账户页默认收起归档账户，点击“已归档账户（数量）”可以展开并恢复。
6. 彻底删除需先展开已归档账户，再点“彻底删除”。预览会列出相关流水、关联转账／退款及其他账户余额变化；输入完整名称确认后先自动备份再执行。删除不能在软件内撤销，旧备份仍保留原数据，备份恢复可找回。若会破坏其他账户的历史余额则不允许删除。
7. 备注框下显示当前分类最常用的 5 条已保存备注，点击只填入、不提交。更换分类会切换建议，作废／修改／删除后更新，重启后仍可使用。
8. 用“数据管理”备份和恢复。备份不加密，保存到信任的位置；当前上限 8 MB。

总览的账户净额包含资金、应收本金和负债；含投资的净资产另列，缺估值时提示已知小计。负债账户暂不支持普通收入、负债之间转账或负的欠款余额。

## 借还款使用

日常账本的“类型”选择“借还款”，再选我借入／我还钱／我借出／收回借款。新借入或借出填写对方姓名，软件自动建立记录；也可以选择已有对象继续增加本金。归还或收回选择欠款与实际资金账户，支持分次处理，禁止超额。

账户页将“我欠别人的”和“别人欠我的”单独展示，支持直接还钱／收回；零余额记录默认折叠。旧负债账户直接复用原名称与余额，不重新录入。已存在但尚未录入的欠款可以新增负债／应收账户并填写期初本金。

新借还款只记本金，不记利息；利息请另记收入或支出。同一方向按对象汇总本金，不拆分合同、期限或利率。含手续费的旧流水保留原编辑表单；无手续费的借还流水使用简化编辑，操作和对象固定，可修改资金账户、日期、金额、备注。

首次运行 0.4.0 会将账本升级至 schema v3，升级前在账本 backups 目录保存 before-v3 备份。旧程序不能打开升级后的 v3；回退请使用升级前备份的独立恢复副本，不覆盖唯一账本。更新前先退出旧程序，替换整个程序目录，账本仍保存在用户数据目录。

## 历史分类汇总

1. 数据管理 → 选择历史汇总 JSON。已整理的鲨鱼记账待迁移格式可直接选择，无需改原始文件；格式样例见 docs/11-history-import.md。
2. 核对日期区间、各期间合计、原分类及目标分类、来源、覆盖明细净额和本项报表变化。待映射分类只能选择同方向分类，修改后点击“按当前分类重新预览”。没有合适分类时先在日常账本新增分类，再返回选择文件。
3. 重复或期间重叠不允许确认；不会自动覆盖旧汇总。核对截止日并勾选覆盖规则后点击“确认导入历史汇总”。预览有效 10 分钟，账本变化需重新预览；失响应后可直接重试相同确认，不会重复导入。
4. 批次列表查看期间、金额、原分类、映射、来源标识和哈希。撤销先预览变化，再勾选确认；原始 JSON 与批次保留，之后可重新预览导入。

有效汇总影响月收支，不改变账户余额；被覆盖明细在流水中有标注，范围外记录照常计入。部分月份不代表整月完整，汇总不拆成逐日数据。截图图片未纳入备份，需要单独保留原件；JSON 来源和汇总已随完整备份保存。

0.5.0 升级历史：首次打开旧账本升级至 schema v4，并保留 before-v4 备份。每份来源 JSON 限 512 KB、24 个期间、500 行；备份受 8 MB 上限约束。分类图表和预算已在 0.6.0 增加，OCR 与整段明细核对替换仍待开发。

## 日、周、月、年度收支报表（0.6.0）

进入“报表与预算”，选择日报表／周报表／月报表／年报表，然后分别选择具体日期、对应 ISO 周、月份或年份。上一／下一期间和返回当前期间可快速切换；周一为周首，当前期间截至今天。展示收入、净支出、结余、日均、实际上期日期与变化，年趋势按月，其余按日。空白记录不能证明真实无收支；日均按所列自然日天数计算。

若所选日／周截取了历史汇总，相关金额显示待核对，另列可定位小计；历史来源说明原范围，月度总额不会拆到每天。前后期间比例只有双方金额可计算且上期非零时才显示。负净支出为退款净额。分类排行可选收入／支出，点击查看构成；构成可按方向和分类筛选、翻页。

“导出当前构成 CSV”包含原记录金额、计入金额、来源、期间及统计状态。历史汇总无法分配时计入金额留空，已覆盖明细计入金额为零；原金额仍留作凭证，不要将原金额列直接求和当作日／周支出。文本已防表格公式注入，文件使用 UTF-8 BOM，最多 50000 行，超过时缩小期间或分类。

## 可选分类预算（0.6.0）

预算不必设置。未配置的分类没有额度卡或已用／剩余数字。点击“分类预算（选填）”或页面下方设置入口，独立选择预算月份与支出分类，填写正金额；可调整或移除，移除后额度立即隐藏，再次设置仍可用。

仅已设置的分类显示月额度、已用、剩余／超支和比例。退款抵减发生月支出，净退款时已用为零，不额外增加额度；80% 接近、100% 用尽、超过时超支，仍能正常记账。未来月份只显示计划额度，未到期不显示虚构消费。沿用上月须手动点击，只补充本月未设置分类，不覆盖现有额度，不自动续期、结转。

如在另一个窗口补记收支，可点击“刷新预算”重新读取该月使用情况；预算与报表各自按所选期间刷新。

0.6.0 升级至 schema v5 前保存并验证 before-v5 备份。完整备份包含预算，支持旧版账本升级；旧程序回退仍需使用升级前备份的独立副本。当前只有人民币月度分类预算，不含年度总预算或多级预算。

0.6.1 的日报不再显示单点趋势；周／月每日、年每月从左至右排列。点击或聚焦柱组查看具体金额；负值位于零线下方，缺失和未来不填零。窗口较窄时在图内左右滚动。此更新仍使用 schema v5，不需要新增迁移。

## 投资基础（0.7.0 / M3.1）

1. 在账户页建立证券现金或基金使用的资金账户，期初填当时实际剩余现金，不含持仓市值；已有账户可直接复用。
2. 投资 → 标的与估值，选类型、市场、六位代码和名称。相同市场＋代码不可重复，代码仅作本地标识，不联网校验名称。
3. 记一笔投资 → 期初持仓，填数量和剩余总成本；未知成本留空。有历史买卖时从第一笔买入录入，不再重复建立期初。
4. 买卖／申赎填成交／确认日、实际份额和成交金额，费用合计默认零、可展开；也可选实际扣款／到账，费用已包含，不再加扣。股票和 ETF 数量整数，基金最多八位小数；不验证下单手数或交易日。
5. 标的与估值填写价格／净值日期及元／股（份）价格，每个标的单独保存；同日修改需最新版本，作废恢复最近有效价。跨账户同标的共用价格，始终显示估值日期；不自动联网。
6. 我的持仓默认隐藏清仓项，可按账户／类型筛选、进入明细。成本未知时先修改期初记录补齐总成本，再卖出；无价格时不按零估值。
7. 投资记录可修改或作废，整段重算成本和现金。不足时拒绝，提示冲突日期和流水序号。账户、标的与操作不能直接改，须作废重录。含投资历史账户当前不能彻底删除，持仓未结清也不能归档。
8. 更新前先退出旧程序；首次打开 v5 账本前自动保存并验证 before-v6 备份。投资事实、价格及修订都随完整备份恢复。回退用旧程序和升级前备份的独立恢复副本，不直接打开升级后的数据库。

当前显示期初之后的盈亏金额，不推算期初前收益、年化收益或历史净值曲线；分红、再投与拆分待 M3.2，投资 CSV 与期间报表待 M3.3。投资页在同一快照读取个人规模的全量投资记录，界面每页 20 条，尚未做大数据量性能承诺。
