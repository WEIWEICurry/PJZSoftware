# M4.2 统一启动与更新管理

## 验收与范围（实现前确定）

1. Windows 标准用户无需管理员权限。原便携方式保留；通过启动窗口首次设置固定入口，复制完整已校验发行版到用户目录 application/versions/独立版本槽，固定 PJZStart.exe 派发当前版本，可创建桌面快捷方式。程序目录与账本始终分离，不搬动、删除账本。源码运行不安装固定入口。
2. 发行包包含 release.json（格式、启动协议、版本、schema、完整文件大小／SHA256），验证路径、符号链接、大小／数量、哈希与必需文件；原子发布版本槽后方可使用。校验和发现损坏，不代表发布者数字签名；只选择可信来源的本地包。无后台联网更新。
3. 启动窗口和页面显示实际后端版本、程序位置和固定入口。重复启动只有同版实例可唤起；不同版或无法辨认的旧实例要求先退出，不强制结束其他进程，不静默复用旧版。
4. 原生启动管理选择本地 ZIP，显示当前／目标版本与路径，再确认。新包先在合成临时账本自检；当前服务正常停止、在途请求完成并保存恢复保护备份后，才提交候选指针。新进程就绪握手成功再切换 active；超时／失败保留当前指针和备份，尝试重新打开原版。仅允许相同 schema 的本地更新／回退，跨 schema 提示使用独立备份恢复，禁止自动降级数据库。旧版本文件不自动删除。
5. 有上一版本时可从启动管理回退程序；同样先备份并用就绪握手确认。回退程序不回退数据。每个固定入口同一时间只运行一个账本服务，切换前释放旧锁。
6. 恢复成功返回短期一次性令牌；页面按钮仅发送令牌，原生启动窗口再确认。只允许本进程刚验证产生的恢复目录，HTTP 不接收任意程序或账本路径。退出并保护当前账本后候选指向恢复副本；失败回到原账本，原文件不被覆盖。
7. 固定启动器与主程序分离，不在运行中覆盖 executable。配置和指针原子写入，候选损坏／中断不会使当前指针丢失。首次入口设置失败不改原便携目录。更新功能不提供任意执行 HTTP 接口。

## 验证

合成发行目录／账本验证清单完整性、Zip 穿越／大小／重复／链接、损坏与部分安装、指针原子写入、失败回退、候选就绪握手、相同版本重复启动与不同版本拒绝、schema 不兼容、更新前备份失败、受控恢复令牌及过期／重复／任意路径拒绝。浏览器用合成 API 验证版本与恢复打开；Windows 成品核对双 exe、固定入口安装、启动和升级失败回退；无真实账本／桌面变更用于自动测试。实际结果随交付记录。

限制：首版无发布者签名、后台下载、跨 schema 自动更新、版本自动清理或卸载向导；固定入口协议 v1 启动器首次复制后保持，未来协议变更需单独兼容升级。恢复仍先生成独立副本，不自动覆盖唯一账本。

## 0.16.0 实际验证

完整 252 项后端测试通过，新增 33 项覆盖发行包完整性与路径边界、schema 不兼容、部分安装失败、原子提交失败、启动握手与超时、旧实例／遗留元数据识别、更新保护备份失败、受控恢复令牌及过期／重复提交。4 项浏览器测试通过，包含实际运行版本、原生管理请求及恢复按钮仅发送令牌；合成页面已目视检查。

Ruff／格式（含 launcher）、mypy、契约同步、Prettier、ESLint、类型与 Next 静态构建通过。实际 Windows 双 exe 在精简 PATH 完成启动、认证、自动备份、重复启动与异常恢复；实际固定入口在临时合成目录完成就绪握手、版本槽切换、损坏候选失败回退、恢复副本切换并核对原账本未被替换。强制结束的故障注入等待拥有的子进程完全退出后再重开；原生桌面快捷方式自动测试未改动用户真实桌面。完整 ZIP 与 SHA256 在交付时生成；CI 状态以当前 PR 为准。

## Windows CI 路径别名回归验收

成品探测的临时根目录须先 resolve，兼容 Windows GetTempPath 返回 RUNNER~1 等 8.3 别名；写入指针的测试账本路径也统一为规范路径。不得通过移除版本槽链接／越界检查来绕过失败。异常清理只遍历测试自身记录的合成账本目录，不依赖可能无效的 current.json，仍核对进程路径并等待拥有的进程退出；避免首次错误被清理失败遮盖。用真实短路径别名执行完整双 exe 探测，CI 通过后再合并。

## 0.16.1 安静启动验收（实现前确定）

- 正常交互启动直接打开浏览器账本；本地服务管理窗口在 Tk 创建后立即隐藏，避免首次映射闪现。固定入口与便携启动一致，无需改快捷方式参数。
- 同版重复启动只重新打开账本，不显示或抢占服务管理窗口。页面“启动与更新管理”及恢复副本确认可按需显示管理窗口。
- 关闭管理窗口只隐藏，不退出后台服务；页面与管理窗口的“退出软件”仍正常停止服务、完成备份并释放锁。窗口明确说明此行为。
- 浏览器确实无法打开时显示管理窗口以便重试；提供 --show-service 排障参数。--headless 的自动探测不创建 Tk 窗口，--no-browser 不打开真实浏览器。
- 事件回归验证默认隐藏、重复启动、管理唤起、关闭隐藏和显式退出；实际 Windows 成品使用合成数据、仅枚举所拥有进程的窗口验证默认不显示服务窗口，继续运行原有固定入口／更新回退／恢复切换验收。金融数据、schema v9、启动协议 v1 不变。

0.16.1 实际验证：完整 261 项后端测试、4 项浏览器测试通过；窗口专项覆盖隐藏、重复启动、管理唤起、关闭隐藏、显式退出、恢复确认及 --no-browser。真实 Windows 短路径环境的最终双 exe 验证通过，实际枚举自有交互进程确认无可见服务窗口且重复启动保持隐藏；同时通过固定入口、更新失败回退与恢复切换验收。Ruff／格式、mypy、契约、前端格式／ESLint／类型及静态构建通过；无数据库迁移，未读取用户真实账本或修改桌面快捷方式。CI 以当前 PR 实际状态为准。
