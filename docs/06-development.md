# 开发规范、质量与实施计划

## 1. 工作方式

需求 → 验收条件 → 设计／契约 → 实现 → 验证 → PR 评审 → 合并 → 发布。小功能可共用一份 PR，不要求每次写长文，但数据、统计和安全口径必须有依据。先做能运行的技术纵切，再逐模块增加业务。

首版单仓库：frontend/、backend/、launcher/、contracts/、docs/。不建微服务，不引入远程数据库。设计文档随实现修订，未实现项不标“已完成”。

## 2. 代码规范

- 前端 TypeScript strict，ESLint／Prettier；Python 类型注解、Ruff、mypy。组件负责交互，领域计算在 Python。
- Pydantic 校验所有 API 输入，生成 OpenAPI 与 TypeScript 契约。数据库只用参数化查询／ORM；迁移脚本受版本管理。
- 精确数值遵循数据模型，业务金额禁止 float。错误有稳定 code 和可读中文提示。
- 事务包含事实、投影、幂等与本地修订。禁止捕获异常后返回成功；异步失败须能重试且不重复写入。
- 依赖有实际用途并固定锁文件；不为小功能引入庞大框架。升级前检查官方兼容性。
- 日志只含错误码、非敏感技术状态和随机 request_id，不记录财务内容。
- 注释解释原因与边界，避免复述代码；公共领域行为有明确输入、输出与失败条件。

## 3. Git 与 GitHub

主分支 main 保持可构建；功能分支 feat/<topic>，修复 fix/<topic>，文档 docs/<topic>。初次设计基线可直接提交，后续业务通过 PR。提交格式示例：docs: 建立产品设计基线、feat: 增加账户转账、fix: 修正清仓尾差。

提交前检查 diff、暂存路径与数据排除规则；禁止强制提交个人资料、签名密钥、安装产物。PR 使用仓库模板，说明问题、行为、验证、数据库与数据影响。

推荐 main 保护规则：通过必需检查、禁止强推、合并前审阅。这里只给出建议，不假称已在 GitHub 开启。个人开发也保留自审与检查记录，不以无人评审绕过金融数据验证。

标签：v0.x.y；有数据库变化的发布必须记录兼容范围、迁移与回退方式。发布包校验和与版本对应；签名与自动发布后续单独确定。

## 4. 质量门槛

| 层次 | 有意义的验证 |
| --- | --- |
| 领域 | 转账收支不变、买卖成本与现金流一致、清仓无尾差、分红不重复、退款口径 |
| 数据库 | 事务回滚、外键、并发冲突、幂等、旧版本迁移、崩溃后完整性 |
| 历史导入 | 重复文件、重排文件、总额不符、分类映射、部分明细覆盖和整段替换 |
| 接口 | 未认证拒绝、Host／Origin／CSRF、数值边界、分页、版本冲突 |
| 前端 | 关键表单与错误状态、可访问性、金额显示；不镜像后端计算写冗余测试 |
| 端到端 | 创建账户→记账→转账→买卖→备份→空目录恢复，余额／持仓／报表一致 |
| 安装包 | Windows 标准账户、中文路径、断网、无开发环境、单实例、退出、更新保留数据 |

回归测试只使用合成数据。金融计算测试用独立手算结果与不变量验证，不能只断言与实现函数相同的公式。

M0 建立 CI 后运行：前端格式／lint／typecheck／测试／静态构建，后端 Ruff／mypy／pytest，契约同步检查，以及 Windows 打包冒烟。当前仅文档阶段，没有这些应用命令和 CI，不把未来检查列为已通过。

文档变更检查链接、过时方案、Git diff 格式和敏感文件排除即可，不为凑数增加应用测试。

## 5. 实施里程碑

| 阶段 | 可交付结果 | 退出标准 |
| --- | --- | --- |
| M0 基础验证 | 仓库脚手架、Next 静态页、FastAPI 本机会话、SQLite、启动器、锁文件、基础 CI | 无开发环境的 Windows 打包启动、离线、安全接口、备份恢复通过 |
| M1 日常账本 | 账户、期初、收支、退款、转账、负债本金、余额校正与修订 | 重启数据一致；统计与余额口径验证通过 |
| M2 历史迁移与报表 | 旧汇总预览导入、去重核对、预算与报表、CSV | 不重复入账；缺少逐日数据明确提示 |
| M3 投资管理 | 标的、买卖、费用、分红、再投、拆分、手动价格、总览 | 手算样例、历史修订重算、成本未知及估值缺失处理通过 |
| M4 首版发布 | 完整数据管理页、自动备份、异常恢复、安装包、用户指南 | 全流程换机恢复与断网验收；无阻断问题 |

不承诺未经测量的工期。首个实施任务是 M0，不直接铺开所有页面和业务代码。

## 6. 完成定义

验收条件满足、相关设计同步、适当自动与人工检查通过、没有私密数据进入仓库、数据迁移可恢复、已知限制写清、代码经过 PR／自审。涉及备份时必须实际恢复，涉及金额时必须有独立算例，不能以页面能打开当作完成。
