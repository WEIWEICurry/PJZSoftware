# 隐私、备份与历史迁移

## 1. 保护边界

用户选择首版无需应用密码，因此数据库、附件、导出及备份默认不做应用层加密。Windows 账户权限提供基本隔离；不能防御已登录账户下的恶意程序、共享账户或被拷走的磁盘。磁盘加密可由用户自行开启，软件不替用户修改系统策略。

无埋点、广告 SDK、远程崩溃日志或云同步。不调用真实银行／券商凭据。数据管理页准确显示此状态，不能仅用“本地”暗示已加密。

代码仓库忽略 data/、backups/、exports/、logs/ 及数据库文件；提交前仍人工检查暂存列表。真实财务数据不进入测试、CI、Issue 或 PR。将来如发布演示图，必须用合成账本。

## 2. 数据布局

建议 Windows 用户目录下 PJZSoftware/ledgers/<ledger-id>/ 存储 ledger.sqlite3、attachments/、元数据。安装目录只含程序和静态资源。应用显示完整路径；位置迁移须停写、备份、验证后切换。

备份放在独立可配置目录；同盘备份只能应对误操作，不能保证硬盘损坏后可恢复。软件建议另存移动硬盘，不默认把数据放入云盘。

## 3. 备份格式 v1（拟定）

扩展名 .pjzbackup，ZIP 容器：

- manifest.json：格式版本、应用版本、数据库 schema、账本 ID、生成时间、每个文件的大小与 SHA-256、合成的结构数量摘要。
- ledger.sqlite3：通过 SQLite Backup API 生成的一致性快照。
- attachments/：所有被引用附件，以相对路径存储。

禁止直接复制运行中唯一的 .sqlite3 文件当作完整备份，特别是 WAL 模式。生成快照期间协调写锁与附件生命周期，使数据库引用和附件集合对应。先写临时包，验证完整性后原子改名；失败保留旧备份。SHA-256 用于发现损坏，不等于加密或签名认证。

默认策略：发生写入的自然日生成一个完成的每日自动备份（长时间运行也需触发）；保留最近 14 个成功每日备份。手动、升级前、恢复前备份不被自动轮转删除。只有新备份验证成功后才清理过期项；失败显示持久提示和重试入口。具体执行时机在 M0 测试崩溃与退出路径。

## 4. 恢复流程

1. 校验体积、清单、文件哈希和格式；拒绝绝对路径、..、符号链接及过量解压，防止 ZIP 路径穿越与解压炸弹。
2. 不覆盖现有账本；现有账本先生成可恢复备份，目标采用全新临时目录。
3. 检查数据库完整性、外键、附件、记录数量和业务不变量。
4. 旧 schema 先在临时副本迁移后验证；更新版本的 schema 明确拒绝，禁止强行降级。
5. 重建余额与持仓投影并核对，全部成功后原子切换账本；失败清理临时目录，保留原账本及恢复包。
6. 在空白 Windows 用户目录做恢复验收，比较业务数据，而不是要求数据库二进制文件逐字节相同。

备份格式与数据库 schema 独立版本化。CSV 是可读、可分析导出，不是完整恢复格式；CSV 中以 =、+、-、@ 等开头的用户文本按表格安全方式导出，防公式注入，数值列保持正确类型约定。

## 5. 鲨鱼记账迁移

本地已有 data/shark-import/ 下的截图、分类记录与 expense-summary.json。这些是用户真实资料，均不提交仓库。旧文件保持原样，由导入适配器转换，不要求改写原始凭证。

适配器校验 schema_version、CNY、单位 fen、期间、分类金额和总额；分类先映射，再事务写入。原 staged_not_imported 状态只说明待迁移，不代表软件中已有账本。

去重同时检查原文件 SHA-256 与规范化内容摘要；更名或重排同一份汇总不能重复记账。重复金额的不同真实交易不能仅凭金额去重。预览显示新增、重复、冲突、分类映射及覆盖关系；冲突不自动覆盖。

截图解析仅依据可辨认文字，不从折线图反推日期和金额。不清晰数据进入待确认项。后续逐笔截图按数据模型的覆盖规则替换汇总，不能把两者叠加。

## 6. 数据库升级

每次 schema 迁移前备份；版本顺序、迁移脚本摘要和结果本地留存。尽可能事务执行；涉及文件或非事务步骤时用可恢复的阶段标记。失败停止写入并提供恢复路径，不创建空账本掩盖失败。不承诺未经测试的降级；回退用旧程序与对应旧备份。

## 0.5.0 已实现的历史来源边界

预览只读取用户选择的 JSON 内容，不根据来源字符串访问任意文件。确认后，原 JSON 字节与映射、文件及内容摘要、汇总事实存入数据库并随完整备份保留；图片只保存标识，当前不复制／打包原截图。原始待迁移 JSON 与截图不覆盖，状态不回写。导入和撤销绑定账本版本与幂等凭证，同一事务提交；撤销保留来源。

备份验证除现金投影外，还核对 JSON 原始哈希、规范摘要、分类方向、映射后的行和有效区间不重叠。schema v4 升级前保留 before-v4 备份；接受 v1～v4 恢复，旧程序回退须使用升级前备份的独立副本。每日自动轮转、截图附件和账本切换仍属后续范围，不能据本节视为已完成。
