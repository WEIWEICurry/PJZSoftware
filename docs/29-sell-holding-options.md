# 卖出标的按持仓筛选

## 验收条件

- 新建卖出按持仓账户筛选正份额标的，买入默认按持仓账户筛选，首次买入可显式选择新标的；不以扣款/到账账户筛选。
- 未选择账户或无可卖持仓时禁用标的选择，显示明确提示并禁止提交。
- 切换卖出持仓账户清空标的和数量；切换标的清空数量。切换卖出操作清除不匹配标的。
- 当前卖出显示当前持有份额；补录历史卖出按确认日结束时重放的持仓筛选（新增记录排在当日已有记录后）。历史日后才买入的标的不出现，后来清仓的标的在历史有份额时仍出现。
- 历史持仓由版本化本地认证 API 返回十进制字符串，前端不计算账务；查询等待/失败不可使用旧日期结果，支持重试。
- 编辑旧卖出保留锁定的原账户和标的，不受当前清仓影响；数量提示明确是当前剩余而非历史可售额度。
- 后端最终交易仍完整重放并校验份额、成本、现金和后续事件；选项只是辅助，不保证一笔历史插入必定成功。
- schema 11 不变，无数据迁移。

## 实现与验证

只读 GET /api/v1/investments/sell-options 使用 UUID 与日期校验、既有本机会话及 Host/Origin 保护。在同一只读事务按确认日重放，返回该账户正份额标的及精确份额字符串。今天录入复用已加载当前持仓，历史查询以账户/日期/持仓快照识别结果，忽略过期响应，失败可重试；不以当前价格或资金账户余额推断历史份额。

274 项后端测试与 10 项浏览器测试通过；覆盖历史买入前、当日买入、后续清仓、支付与持仓分离、只读不改账、历史插入被后续超卖拒绝，以及表单无账户/空账户、切换清空、份额提示、历史失败重试、延迟响应隔离、买入全量标的和历史清仓编辑。Ruff/格式、mypy、ESLint、TypeScript、Prettier、契约同步、静态构建和自检通过。

限制：选项是当日已有交易结束后的份额，不是平台冻结/在途状态，也不保证插入历史交易后所有后续交易仍合法；保存继续以完整重放结果为准。

Windows 成品验收通过：精简 PATH、资源、本机认证、自动备份、重复启动、崩溃恢复、安静窗口、固定入口、本地更新与失败回退、恢复副本切换；ZIP 完整性及逐文件静态资源校验通过。

## 0.22.2 账户与标的联动验收

- 新建投资先选择持仓账户，默认只显示该账户在持仓投影中的标的，含已清仓标的，方便再次买入和补录历史。
- 买入与期初提供「选择该账户的新标的」，勾选后显示全部已建立标的，允许首次投资。空账户有明确提示和此入口。
- 切换账户清空标的与份额，并退出新标的模式；切换操作清除不符合新模式的标的。
- 卖出沿用确认日正份额筛选及失败重试。编辑历史记录保留锁定的原标的。
- 截图匹配的新标的可预填，并自动勾选新标的模式；扣款账户不参与筛选。
- 保存或取消后恢复默认账户筛选模式。无 schema 变动。

0.22.2 本地验证通过 288 项后端测试、12 项浏览器测试，含账户切换清空、空账户新标的入口、关闭新标的模式、首次期初与买入、截图自动启用新标的模式、历史卖出与历史编辑。干净 npm ci、格式、静态检查、类型检查、契约、构建与自检通过；界面截图使用合成数据核查。
