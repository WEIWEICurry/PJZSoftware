# 投资首页待办区

## 验收条件

- 在投资「我的持仓」首页显示四类待办及数量：已生成的定投待核对项、缺少有效估值的正份额持仓、有效估值超过 7 个自然日未更新的持仓、剩余成本未知的正份额持仓。
- 定投数量为草稿条数，其余分别按标的／账户持仓计数；同一标的跨账户的净值任务合并。因分红折算使旧估值失效的持仓计入缺有效估值，不同时重复计入旧估值。
- 忽略已删除计划、已确认／已跳过项和未来计划日。暂停计划已有待核对项保留；涉及归档账户时提示需恢复。未生成草稿不推定为已扣款或漏记交易。
- 使用只读认证 API，同一事务快照内返回账本版本、统计日和任务列表。无自动生成、写账或联网查询。
- 定投待办点击带入计划、最早待核对日及最多 366 天范围，并自动读取该范围草稿；更久积压分段处理。
- 估值待办点击定位指定标的的估值输入与基金查询预选，联网保持用户主动启用。成本待办点击定位账户和标的相关投资记录。
- 首页返回、持仓／净值／定投操作后读取新待办。加载和失败显示明确状态，失败可以重试，不能显示成零待办；忽略过期响应。
- 空状态显示无需处理。支持按类别展开列表，避免大量历史草稿挤满首页。schema 11，无迁移。
- 验证只读、重复合并、7 天边界、未来估值／草稿、暂停删除、归档、超一年范围与关键跳转，截图与测试只用合成数据。

## 实现与验证

0.25.0 已实现。新增认证只读 GET /api/v1/investments/todos。304 项后端测试、18 项浏览器测试通过，覆盖跨账户合并、未来与零份额排除、估值 7 天边界、折算后失效价格、暂停删除与归档、超过一年日期范围、只读修订不变，以及待办跳转、自动读取草稿失败重试、联网未自动发出、处理后刷新和过期响应隔离。干净 npm ci、格式、静态、类型、契约、构建及本地自检通过，界面截图使用合成数据核查。

待办面向全部账户，定投只统计已生成且未处理的草稿。7 个自然日是提醒阈值，数据更新仍由用户主动操作。
