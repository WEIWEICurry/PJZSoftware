# 多张基金回执批量录入

## 验收条件

- 独立批量入口，保留单张填入表单。一次最多 20 张，累计最多 40 MB，每张 PNG/JPG 5 MB、1200 万像素上限沿用 OCR。
- 本机按顺序识别，每张独立状态；成功项保留，失败可重试。选择图片不自动识别，识别不写账。
- 内容 SHA-256 相同的图片不重复加入；识别后展示队列，可排除或移除。当前图片和可编辑草稿并列，自动匹配标的和账户、净值日沿用现有规则。
- 每张需人工勾选核对。更改字段后重新核对。集中保存前展示选中数量、扣款合计和费用合计。
- 买入采用实际扣款含费口径，费用显式填写。保存必填基金、持仓与扣款账户、确认日、净值日、正份额与金额；净值日不晚于确认日。
- 已有有效买入及本批次相同账户、标的、确认日、份额和实际扣款视为疑似重复，逐张明确允许才可并存。后端在事务中再检查，覆盖并发与批内重复。
- 选中草稿由单次认证版本化接口在一个事务内入账，任一失败整批回滚，复用投资保存和投影重建。支持幂等重试。
- 保存结果不明确时锁定原批次，只能重试原请求确认结果；明确业务拒绝则允许修改。成功后全部标记已保存，不能重复提交。
- 图片、文件名、付款提示和识别原文只保留在当前页面内存，关闭或刷新清理。页面刷新丢失未保存草稿时再次录入仍有交易重复检查。
- schema 11，无新模型和启动加载。测试与截图只用合成数据。

## 验证要求

验证整批余额与份额、业务失败和重复回滚、幂等重试与并发重复、输入限制和认证；浏览器覆盖多文件、相同图片、识别部分失败重试、草稿修改、人工核对、排除、重复提醒、失败保存和成功锁定。

## 实现与验证

0.23.0 使用现有本地 OCR 预览接口顺序识别，新增认证 POST /api/v1/investments/receipt-batches，复用投资保存和事务重建。schema 11。292 项后端测试、14 项浏览器测试通过，含整批回滚、并发重复和断线同键重试。干净 npm ci、格式、静态、类型、契约、构建与自检通过。两张新生成的中文合成回执经真实本地 OCR、浏览器核对及批量保存，独立验证总份额 139.62、成本 15000 分和付款账户余额 85000 分。界面截图只用合成数据。

范围为已确认的支付宝公募基金买入回执。图片与未保存草稿暂存当前页面，关闭面板或刷新后清理。
