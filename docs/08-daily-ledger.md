# M1 日常账本实施与验收

本阶段交付：账户与期初余额、分类、收入／支出／退款、转账与手续费、余额校正、修改／作废、账户归档、月收支汇总。历史截图导入和投资交易仍在后续阶段。

## 数据与统计规则

- 金额输入元、最多两位小数；API 使用整数分字符串，后端整数运算。单笔及任意账户累计不超过 10^12 分。
- 期初日期、交易日期按本地日历日；禁止未来日期及早于账户期初的交易。
- 资产余额不得为负。负债账户以欠款为正；信用消费增加欠款。债务账户不能记普通收入。
- 转账：资产到资产为资金搬移；资产到负债为还本金；负债到资产为借款；负债到负债暂不支持。费用独立计入支出，期初、借还本金和校正不计收支。
- 借款含费用时，欠款增加转账本金，实际收款为本金减费用；资产作为转出方时额外支付费用。
- 退款关联原支出，不能早于原支出，累计退款不能超过原额；按退款发生日抵减支出。可选择实际退款到账账户。
- 所有历史改动重放完整现金时间线；导致任一时点余额不足、关联退款失效或超范围则整笔回滚。金额同日按创建顺序核算，暂不提供手动同日调序。
- 作废保留原记录与修订；有有效退款的支出不可直接作废。归档账户保留流水，零余额才可归档，不允许新增或修改指向归档账户的流水。
- 财务写请求带幂等键；同键同内容返回原结果，同键不同内容拒绝。修改／作废带 revision，重复或过期更新不覆盖新数据。
- 月汇总仅含已实现的普通收支、退款及转账费；资产概览只含账户现金与负债，证券现金不代表持仓总资产。

## 实体落地

schema v2 使用 accounts、categories、financial_events、cash_entries、operation_revisions、idempotency_records。日常事件的类型特有字段集中在 financial_events，暂不拆分 daily_transactions／transfers 等一对一子表；金额仍为 INTEGER，外键和检查约束必须启用。账户余额从有效 cash_entries 汇总；流水列表按期间／账户／类型／分类分页筛选。

Alembic 管理 v1→v2，升级前生成并验证 v1 备份，升级事务失败保留原库。v1 备份可恢复到临时新目录后升级为 v2。原始库、备份、用户截图都不得进入 Git。

## 验收清单

1. 1000 元期初→支出 30.25→收入 200→转账 100 及费用 1，资产总额 1168.75，月收入 200、月支出 31.25。
2. 退款在新月份抵减该月支出，关联上限和历史修改约束正确。
3. 借款／还款本金不进收支；欠款与净资产计算正确。
4. 幂等重试不重复扣款；并发更新只有一个成功。
5. 历史支出增大导致后续不足时回滚；作废收入影响后续余额时拒绝。
6. 旧版账本升级、失败回滚、v1 备份恢复、完整 v2 业务数据备份恢复可重现。
7. 浏览器实际完成建账户、收支、转账、修改／作废、备份恢复；重启保留数据。

## 0.26.2 账户直达流水验收条件

账户卡片的名称和余额组成可点击链接，并显示“查看流水”提示；保留独立编辑、归档、借还及删除操作。支持键盘聚焦与新标签打开，归档账户同样可查。链接使用 /journal/?account_id=账户ID，刷新和浏览器返回保留入口的账户范围。

从账户进入时默认全部日期、全部类型和分类，分页查看该账户作为转出方或转入方的日常流水（含期初、作废与借还本金）。可关闭“全部日期”按月查询，或切换账户、类型及分类；普通日常账本入口仍默认本月全部账户。明确说明投资交易在投资记录中查看。筛选切换回到第一页，迟到响应不得覆盖当前筛选。

使用合成账户验证入口、归档账户、刷新及历史导航、跨月和转账双向筛选、分页、筛选清除，以及编辑归档操作不会触发跳转。本功能只调整导航与查询展示，无数据库迁移。

0.26.2 本机验证：318 项后端回归、21 项 Playwright、格式／lint／mypy／类型／契约／静态构建及合成自检通过。合成测试覆盖跨月转入转出、账户链接、归档、新标签、刷新、返回、分页和筛选清除。实际 Windows 包的最小 PATH、启动／单实例、认证、自动备份、更新／失败回退探测通过。


## 0.26.3 投资资金流水验收条件

账户入口默认勾选“包含投资资金流水”，按实际扣款/到账账户查看日常与投资记录，时间、类型、分类筛选后统一分页。普通日常账本仍默认仅日常流水，可主动包含投资。投资买入显示实际扣款（含费用）、卖出显示实际到账（扣费后）、现金分红显示到账，再投仅显示另付费用；持仓期初、折算和无另付费用的再投不属于资金流水。持仓平台不因代持标的而显示银行卡扣款。

投资行标注标的、持仓账户、实际资金账户及资金方向，取已有整数分现金投影，费用不重复扣。作废投资保留凭证，标注未影响余额，不把原金额误作有效现金。投资行只读，修改通过投资管理完成，不开放日常编辑/退款/作废。投资现金不纳入日常收支、分类预算或历史覆盖统计，不修改账本或数据库结构。

使用合成记录验证跨银行卡支付、同账户支付、买卖手续费、分红、再投费用、无现金动作排除、作废、筛选分页及原日常统计保持一致。浏览器验证默认开关、投资标签、真实扣款金额和只读操作。

0.26.3 本机验证：320 项后端回归、22 项 Playwright、Ruff／mypy／契约、前端干净安装／格式／lint／类型／静态构建通过。新增合成测试独立核对两张银行卡的买入扣款、卖出到账、分红、再投费用和作废凭证，核对日常收支未重复计入；浏览器验证实际金额、账户信息、筛选开关和投资行只读。


## 0.26.4 流水方向与逐笔余额验收条件

流水金额按账户实际变化显示正负号，增加为红色、减少为绿色，零变化保持普通颜色；金额下用小字显示该笔发生后的账户余额。余额从完整有效现金投影按发生日期及同日顺序累计，包含期初、转账、投资和校正，再应用界面期间、分类、类型、账户与分页筛选。筛选和翻页不得把历史余额重置为零；历史修订或作废后重新查询展示当前事实重算的余额。

全部账户视图的转账分别展示两侧实际变化与余额，单账户筛选只显示该账户的一侧，转出金额包含手续费，不重复加扣。投资按实际资金账户显示同样的方向和余额。负债小字标为“欠款”，应收标为“待收回本金”，正负号代表该余额的增减，避免把借还本金误作日常收入。作废凭证显示“已作废，未影响余额”，不虚构逐笔余额或以原金额当成有效资金变化。

采用现有整数分现金投影和 SQLite 窗口累计生成只读模型，不写入新的余额快照，不改变统计和数据库结构。验收用合成手算覆盖跨月、同日顺序、过滤分页、双向转账手续费、投资、退款、校正、负债应收、作废与修订重算；浏览器验证正负号、红绿色和小字余额、转账两侧与单侧显示。

0.26.4 本机验证：322 项 pytest、23 项 Playwright、Ruff／mypy／契约、前端干净安装／格式／lint／类型／静态构建及合成自检通过。手算覆盖完整时间线、过滤分页、转账手续费、投资、退款校正、负债应收、修订作废和大额整数分精度；浏览器验证红绿色、正负号、小字余额、转账双侧及单账户展示，合成页面已目视检查。
