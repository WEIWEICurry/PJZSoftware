# M1 日常账本实施与验收

本阶段交付：账户与期初余额、分类、收入／支出／退款、转账与手续费、余额校正、修改／作废、账户归档、月收支汇总。历史截图导入和投资交易仍在后续阶段。

## 数据与统计规则

- 金额输入元、最多两位小数；API 使用整数分字符串，后端整数运算。单笔及任意账户累计不超过 10^12 分。
- 期初日期、交易日期按本地日历日；禁止未来日期及早于账户期初的交易。
- 资产余额不得为负。负债账户以欠款为正；信用消费增加欠款。债务账户不能记普通收入。
- 转账：资产到资产为资金搬移；资产到负债为还本金；负债到资产为借款；负债到负债暂不支持。费用独立计入支出，期初、借还本金和校正不计收支。
- 借款含费用时，欠款增加转账本金，实际收款为本金减费用；资产作为转出方时额外支付费用。
- 退款关联原支出，不能早于原支出，累计退款不能超过原额；按退款发生日抵减支出。可选择实际退款到账账户。
- 所有历史改动重放完整现金时间线；导致任一时点余额不足、关联退款失效或超范围则整笔回滚。金额同日按创建顺序核算，暂不提供手动同日调序。
- 作废保留原记录与修订；有有效退款的支出不可直接作废。归档账户保留流水，零余额才可归档，不允许新增或修改指向归档账户的流水。
- 财务写请求带幂等键；同键同内容返回原结果，同键不同内容拒绝。修改／作废带 revision，重复或过期更新不覆盖新数据。
- 月汇总仅含已实现的普通收支、退款及转账费；资产概览只含账户现金与负债，证券现金不代表持仓总资产。

## 实体落地

schema v2 使用 accounts、categories、financial_events、cash_entries、operation_revisions、idempotency_records。日常事件的类型特有字段集中在 financial_events，暂不拆分 daily_transactions／transfers 等一对一子表；金额仍为 INTEGER，外键和检查约束必须启用。账户余额从有效 cash_entries 汇总；流水列表按期间／账户／类型／分类分页筛选。

Alembic 管理 v1→v2，升级前生成并验证 v1 备份，升级事务失败保留原库。v1 备份可恢复到临时新目录后升级为 v2。原始库、备份、用户截图都不得进入 Git。

## 验收清单

1. 1000 元期初→支出 30.25→收入 200→转账 100 及费用 1，资产总额 1168.75，月收入 200、月支出 31.25。
2. 退款在新月份抵减该月支出，关联上限和历史修改约束正确。
3. 借款／还款本金不进收支；欠款与净资产计算正确。
4. 幂等重试不重复扣款；并发更新只有一个成功。
5. 历史支出增大导致后续不足时回滚；作废收入影响后续余额时拒绝。
6. 旧版账本升级、失败回滚、v1 备份恢复、完整 v2 业务数据备份恢复可重现。
7. 浏览器实际完成建账户、收支、转账、修改／作废、备份恢复；重启保留数据。
