# 基金买入回执截图试用

## 验收条件

- 在新建投资表单粘贴或选择单张支付宝已确认基金买入回执。原图与识别字段并列核对，应用结果只生成可编辑草稿。
- 用字段标签和行位置解析金额、手续费、份额及日期。区分买入时间、确认日、净值所属日。净值日缺失时按买入时刻和已覆盖的交易所休市安排推算，确认净值供核对。
- 识别标的按代码或完整名称唯一匹配，保持 A/C 类别差异。清除标的名称末尾的导航箭头。持仓与扣款账户分别核对，扣款账户按银行和明确卡尾号唯一匹配，缺失或歧义交给用户选择。
- 预览只读。重复候选提示用户核对，最终保存仍经既有投资接口。金额精确到分，份额使用十进制字符串。
- 本地 OCR 按需加载，安装包内含模型。图片大小与像素受限，结果及原图仅临时用于核对，订单号和卡尾号不写入交易或日志。
- 合成样例验证正常、缺字段、金额冲突、错误文件、未确认回执，以及应用草稿和显式保存。测量成品冷启动及首次识别。
- 独立试用包，使用 schema 11。

## 实现与验证

投资页调用同源认证预览接口。RapidOCR 与 ONNX Runtime 在首次识别时初始化并缓存，PP-OCRv6 中文检测与识别模型和许可证随包发布。运行使用明确的本地模型路径。金额、日期和份额按字段标签解析。两种账户独立匹配或由用户选择。应用草稿后原图保留供对照，关闭或保存时清理。识别范围为单张已确认基金买入回执，支持 PNG/JPG、至多 5 MB 和 1200 万像素。识别结果依赖截图清晰度和版式，无法根据回执和日历确定净值所属日时人工补填。参见 [RapidOCR 模型与许可证](https://rapidai.github.io/RapidOCRDocs/main/en/model_licenses/)。

277 项后端和 11 项浏览器测试通过。完整浏览器流程在临时合成 SQLite 账本上使用真实中文 OCR，并验证实际入账。真实预览接口在测试中禁用 DNS 与新连接后仍完成识别，账本修订号与交易列表保持原样。锁定安装、npm ci、格式、静态检查、类型、契约、静态构建、Windows 成品探针及 ZIP 校验均通过。

同一台机器每版用合成账本启动三个新进程，到本地 /health 就绪中位数为 0.21.4 的 1.06 秒和试用版的 1.04 秒。该指标只覆盖本地服务。打包版 OCR 探针首次 2.03 秒，复用 1.25 秒。试用 ZIP 为 141.9 MiB，上一版 ZIP 为 40.2 MiB。

## 独立试用

解压后在试用包目录运行 `PJZSoftware.exe --data-dir ".\ocr-test-ledger"`，程序将打开独立账本。可在现有版本的启动与更新管理选择试用 ZIP 安装。两版使用 schema 11，更新管理保留前一版时可回退。


## 0.22.1 预填补充验收

2026 年沪深日历由交易所公告核实，随包离线使用。买入时间早于 15:00 且当天开市时建议当天，15:00 起、周末或节假日顺延到下一开市日。回执明确日期优先。时间无法识别、超出日历范围、推算晚于确认日时交给用户填写。草稿标注推算日期，确认保存前仍可修改。基金因跨境市场或临时公告暂停申购时以平台回执为准。参见 [上交所 2026 年休市安排](https://www.sse.com.cn/disclosure/announcement/general/c/c_20251222_10802507.shtml) 和 [深交所交易日历](https://www.szse.cn/English/services/trading/calendar/)。

验收包含名称尾箭头和 A/C 区分，扣款账户同银行多卡、唯一尾号、不同尾号和唯一无尾号候选，以及买入时间紧贴日期、15:00 边界、周末、节假日和超出覆盖年份。
