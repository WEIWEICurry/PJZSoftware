# 历史汇总导入设计与验收

本次实现本地 JSON 预览、分类映射、重复与冲突检查、确认导入、批次追溯和撤销预览。兼容已整理的 schema_version=1、CNY、fen、monthly_category_expense_summary 文件；另支持 monthly_category_summary，期间指定 direction。

汇总不生成交易或资金分录。月收支按期间、分类和方向以有效汇总替代覆盖范围内明细，保留明细对真实余额的作用。预览明确列出明细数量和净额，用户确认覆盖规则；部分月份显示截止日期，不分摊到每天。冲突或映射后重叠拒绝导入，不自动覆盖。

保留原 JSON 字节、文件名、原分类、来源图片标识和原文件及规范内容 SHA-256；不读取来源路径或上传截图。原截图原地保留，备份只含 JSON 来源和汇总。改名、重排、改变空白均不能重复生效。未知分类需映射同方向现有分类，可先新建分类再重试。

schema v4 新增 import_batches 和 historical_summaries。升级前验证备份；接受 v1～v4 备份恢复，验证源数据、哈希、映射和覆盖不重叠。预览有效 10 分钟，绑定账本 revision，提交和撤销均事务幂等；失败整体回滚。撤销保留原始批次，只恢复其覆盖明细的统计，可重新导入。

验收：总额不符、非法币种／单位／版本、负数、浮点、跨月／未来期间、重复 JSON 键、过大文件拒绝；金额使用整数分，允许零。验证文件改名和行重排去重、分类方向错误、重叠冲突、覆盖后不双计（包括退款和手续费）、余额不变、过期／并发拒绝、失响应重试及中途失败回滚。验证撤销影响预览、重启追溯、迁移失败回滚、备份实际恢复及篡改拒绝。端到端只用合成资料，无远程请求。

整段明细核对替换、预算图表、多文件合并属于后续工作；任意截取汇总区间的统计提示缺少逐日数据。

## 文件示例（合成数据）

```json
{
  "schema_version": 1,
  "currency": "CNY",
  "amount_unit": "fen",
  "record_type": "monthly_category_expense_summary",
  "periods": [{
    "start_date": "2026-01-01",
    "end_date": "2026-01-20",
    "displayed_total_fen": 12300,
    "source_images": ["synthetic-source.png"],
    "categories": [{"category": "餐饮", "amount_fen": 12300}]
  }]
}
```

最多 24 个期间、每期 100 个分类、合计 500 行；文件不超过 512 KB，金额可为整数或整数字符串。一个期间只能属于同一个月，日期含起止日。收入汇总用 record_type=monthly_category_summary，并在期间填写 direction=income；支出填写 direction=expense。来源图片标识仅作追溯文字，软件不会按其中路径读取文件。

## 验证记录

本机 52 项后端测试、Ruff 检查／格式、mypy、契约同步、前端 Prettier／ESLint／TypeScript 和静态构建通过。Edge 端到端验证映射、汇总金额及覆盖标记、丢失响应后重试、改名重排去重、撤销预览、撤销后恢复统计、重启与备份恢复，无出站请求。Windows 便携包构建、成品自检和最小 PATH 运行探测通过；成品自检实际导入合成历史来源并验证备份恢复。

真实待迁移文件保持原样，尚未确认导入。GitHub CI 以 PR 的实际检查结果为准。
