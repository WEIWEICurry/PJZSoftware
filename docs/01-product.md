# 产品需求与验收标准

状态：设计基线 v0.1，2026-10-26。

## 1. 目标与用户决定

为个人在 Windows 上持续维护日常账本和投资台账，掌握资产、负债和投资盈亏。重点是数据可控、计算可解释、可换机，不提供投资建议或交易执行。

用户已确定：首版管理人民币、A 股、境内 ETF 和公募基金；不设置应用启动密码，依赖电脑登录保护。默认一个用户、一个本地账本，不做多人并发。

## 2. 首版范围

| 编号 | 能力 | 验收条件 |
| --- | --- | --- |
| R01 | 本地账本与账户 | 可建立现金、银行卡、支付账户、证券现金及负债账户，录入期初余额；重启后数据一致 |
| R02 | 收入与支出 | 新增、修改、作废记录；支持日期、分类、账户、金额和备注；筛选结果与报表一致 |
| R03 | 转账与余额 | 同一事务完成出入两端，原子保存；转账不计入收入／支出；可单列转账费用 |
| R04 | 月度预算与报表 | 按月分类预算、月收支和年度趋势；汇总旧账单列来源；有未覆盖日期时提示数据不完整 |
| R05 | 投资台账 | 维护证券账户和标的；记录买入、卖出、现金分红、基金分红再投、手续费和拆分／份额调整 |
| R06 | 持仓与估值 | 按账户＋标的计算数量、成本、已实现／未实现盈亏；显示估值日期；未估值标的不默认按零元计价 |
| R07 | 资产总览 | 展示现金、可估值投资、负债和净资产；估值或历史数据不完整时说明统计范围 |
| R08 | 历史迁移 | 可预览并导入月度分类汇总，重复导入不增加支出；与明细覆盖关系可核对 |
| R09 | 备份与迁移 | 导出独立备份；空目录恢复后账户、分类、明细、持仓及汇总一致；拒绝损坏包 |
| R10 | 开放导出 | 导出收支、转账、历史汇总、投资交易、估值等 CSV，另提供完整备份；保留记录 ID、类型、期间和来源 |
| R11 | 数据纠错 | 修改历史交易后重新计算后续余额与持仓；会产生负持仓或资金不足时阻止并指出原因 |

R04 的预算只覆盖日常支出；投资买入不消耗消费预算。对缺少账户的旧汇总，不编造资金流或期初余额。

## 3. 不纳入首版

手机端、云同步、在线自动更新、行情自动抓取、券商或银行登录、自动 OCR、自动下单、多币种、融资融券、卖空、衍生品、收益率排名、税务申报和复杂绩效归因。

遇到暂不支持的证券事件时提示该标的计算范围，不能以改备注或调余额掩盖。价格更新、应用加密和多币种可单独立项。

## 4. 统计口径

- 日常收入／支出：来自普通收支记录及明确的转账费用。投资盈亏在投资报表单列。
- 投资申购／赎回、买入／卖出改变证券现金和持仓，不作为日常收入／支出。
- 期初余额与余额校正不是当月收入。负债借入、还本金不是收入或消费；利息可作为支出。
- 净资产＝资产账户余额＋有效投资估值－未偿负债。历史汇总不参与账户余额。
- 首版展示盈亏金额，不在缺少现金流／估值历史时生成貌似准确的历史收益率。

## 5. 发布要求

可安装、离线可用；核心用例通过；用合成账本完成打包版本的备份恢复与跨目录迁移；没有真实财务数据进入 Git 历史。数据丢失、重复入账、金额算错、备份不可恢复均为阻断发布的问题。
